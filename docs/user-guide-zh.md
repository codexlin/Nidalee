# Nidalee 使用指南

## 安装与首次启动

1. 从 [GitHub Releases](https://github.com/codexlin/Nidalee/releases) 下载 Windows MSI。
2. 运行安装程序。Windows 可能显示“未知发布者”，这是因为安装包暂未进行 Authenticode 签名。
3. 启动 Nidalee 并确认 UAC。应用需要管理员权限以可靠发现英雄联盟客户端参数。
4. 启动英雄联盟客户端并完成登录；Nidalee 会自动连接并恢复当前账号数据。

关闭英雄联盟客户端后，应用会切换为未连接并清除账号和当前对局状态。重新登录客户端后会重新发现认证并拉取新会话数据。

## 页面说明

### 仪表盘

展示当前账号、单双排/灵活排位信息、近期战绩和位置画像。战绩范围可以在排位与其他模式之间切换；筛选和分页不会改变账号身份。

游戏结束后，仪表盘会进行有限次数的延迟刷新，以等待 League Client 写入最新对局。

### 对局分析

选人阶段先展示可见的我方成员；敌方在排位选人阶段通常保持匿名，进入游戏后再通过 LiveClient 补齐。排位模式提供严格队列样本、位置与当前英雄适配分析；其他模式只提供近期表现和历史战绩等轻量信息。

点击可识别的玩家卡片可打开详细战绩。机器人和无法获取战绩的玩家不会伪造分析结果。

### 战绩查询

按 Riot ID 查询其他召唤师，并使用与仪表盘相同的排位/其他模式分析能力。快速切换玩家或筛选时，只允许最新请求更新页面。

### 构建中心

“推荐方案”用于浏览并直接应用 OP.GG 构建；“我的方案”用于保存个人符文方案。

自动构建规则固定为：

1. 使用当前英雄和场景中已开启自动使用的个人方案；
2. 没有个人方案时使用在线推荐；
3. 不支持的队列保持客户端现有符文。

当前支持单双排、灵活排位、匹配峡谷和普通大乱斗。详细规则见[构建中心与符文系统](RUNE_SYSTEM_GUIDE.md)。

### 设置

可配置自动接受、自动选禁英雄、自动构建、通知、外观和可选 AI 分析。自动操作在执行前会重新确认当前游戏阶段；用户已经手动操作时不会强行覆盖。

## 海克斯强化侧边栏

侧边栏用于在支持的模式中快速查看强化推荐。窗口可置顶显示，不进行 OCR、游戏内存读取或注入。快捷键隐藏与恢复由全局窗口管理处理。

## 自动更新

应用会读取 GitHub Release 中经过 Tauri 签名的 `latest.json`。首次安装支持 updater 的正式版本需要手动完成；之后版本号递增时可以自动更新。

如果更新检查失败，通常不影响其他功能。可稍后重试，或直接从 [Releases](https://github.com/codexlin/Nidalee/releases) 下载最新版。

## 常见问题

### 无法连接英雄联盟客户端

- 确认客户端已启动并登录，而不只是停留在启动器。
- 确认 Nidalee 的 UAC 请求已允许。
- 退出后重新启动 Nidalee；应用会重新发现 lockfile 或进程认证参数。

### 选人后没有自动应用符文

- 确认设置中的自动构建已开启。
- 确认当前队列受支持。
- 排位需要等待客户端提供有效分路；缺少分路时不会默认套用中路符文。
- 个人方案必须匹配当前英雄和精确场景，并开启“自动使用”。

### 对局分析中敌方仍匿名

这是 League Client 的正常隐私行为。进入游戏并且 LiveClient 可用后，应用会尝试补齐；补齐失败时可对单个玩家重试，不会用错误身份替代。

### 英雄名称或图片暂时缺失

首次启动或游戏版本更新后需要安装静态目录。网络不可用时会优先读取最近一次完整的磁盘缓存；如果没有任何完整缓存，需要恢复网络后重试。

### 如何反馈问题

请在 [GitHub Issues](https://github.com/codexlin/Nidalee/issues) 提供：

- Nidalee 版本和英雄联盟客户端版本；
- 可复现的操作顺序；
- 相关错误日志。

不要公开提交 LCU token、认证 header 或包含其他玩家隐私的完整原始响应。
